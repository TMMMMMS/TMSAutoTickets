# 设计

## Context

终端记录首次发起购买点击为 15:30:06.370。Android 事件记录安全组件于 15:30:08.251 创建、15:30:18.011 关闭，选票 Activity 于 15:30:18.191 创建。Appium 驱动已于 15:30:16.677 结束。事后只读检查在选票页找到了现有的场次容器。

## Goals / Non-Goals

调整定时购票从点击入口到确认场次列表的等待和提示。人工完成官方验证。场次 OCR、库存策略、即时购票与订单提交流程均在范围之外。

## Decisions

- 使用当前前台 Activity 和已有明确验证提示识别此次中间页，兼容已观察到的安全组件只有窗口、没有可读提示的情况。登录和应用切换保留现有人工接手行为。
- 区分普通页面加载和已识别的人工等待，复用现有截止时间及轮询。离开验证页后给正常跳转一个普通加载周期，仍受购票截止时间约束。详情页短暂恢复时继续观察。
- 仅在大麦的场次列表实际可读且原有演出标题检查通过后选场；等待期间不触发点击或返回。普通未知页面继续限时退出。

## Risks / Trade-offs

Activity 名随客户端更新可能变化。缺少可验证的页面标识时沿用普通超时，并在提示中说明正在等待的目标。只读现场核对能验证最终控件，验证过程时序用可控制时钟的测试重放。
